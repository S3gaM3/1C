# 2. Спринт 2 — формы, проведение, роли, интерфейс

Версия конфигурации: `2.0.0.1` (корень конфигурации → палитра → **Версия**). Сначала доделайте объекты из спринта 1, потом формы, потом роли и подсистемы.

Формы — **управляемые**. Если ТЗ не просит конкретную форму, оставьте ту, что платформа рисует сама. Не создавайте лишние обработки и отчёты.

Где в макете две кнопки в одной рамке (Юрлицо / ИП, Клиент / Поставщик, Кошка / Собака) — это не выпадающий список, а **поле переключателя**.

---

## 2.0. Общий рецепт: как создать форму (повторяйте для каждого объекта)

### Форма элемента справочника

1. В дереве раскройте справочник (например `Организации`).
2. ПКМ по ветке **Формы** → **Добавить**.
3. Мастер: тип **Форма элемента справочника**. Имя оставьте `ФормаЭлемента`.
4. Если мастер предлагает отметить реквизиты галочками — отметьте нужные и **Готово**. Если открылась пустая форма — перетащите реквизиты из окна **Реквизиты** (слева в редакторе формы, дерево `Объект`) на холст.
5. Расположите поля сверху вниз как на макете ТЗ: захватите элемент мышью в дереве элементов формы (обычно слева или справа список `Элементы`).
6. Чтобы сделать переключатель: щёлкните поле на форме → палитра свойств элемента (не объекта) → **Вид** = `Поле переключателя`. Для перечисления значения подтянутся сами.
7. Назначить основной: закройте форму, в окне справочника вкладка **Формы** → **Основная форма элемента** = ваша форма (лупа).

### Событие поля (чтобы писать код)

1. Выделите поле на форме.
2. Палитра свойств элемента → прокрутите до **События**.
3. У нужного события (например **ПриИзменении**) нажмите лупу / «увеличительное стекло».
4. Платформа создаст процедуру в модуле формы. Пишите код **внутрь** этой процедуры, не создавайте вторую с тем же именем.

### Модуль формы

Кнопка **Модуль** в редакторе формы (часто внизу или на панели). Клиентские процедуры помечайте `&НаКлиенте`, серверные `&НаСервере`.

### Форма списка

1. ПКМ **Формы** → **Добавить** → **Форма списка**.
2. В списке колонок оставьте те, что на макете (ПКМ по колонке → Удалить лишние, или в элементе таблицы `Список` настройте колонки).
3. Основная форма списка: вкладка **Формы** справочника → **Основная форма списка**.
4. Для дерева: свойства формы списка или свойства таблицы → **Отображение** = `Дерево`.

### Форма документа

Так же, тип мастера **Форма документа**. Стандартные кнопки «Провести и закрыть», «Записать», «Провести» появятся сами, если не снимали командную панель.

## 2.1. Форма элемента Организации

1. Справочник `Организации` → **Формы** → **Добавить** → форма элемента, имя `ФормаЭлемента`.
2. На холсте сверху вниз (перетащите или оставьте из мастера):

   1. `ТипОрганизации` — палитра элемента → **Вид** = **Поле переключателя**
   2. `Код`
   3. `Наименование`
   4. `ИНН`
   5. `Руководитель`
   6. `ДолжностьРуководителя`
   7. `ГлавныйБухгалтер`

3. Полю `ГлавныйБухгалтер` запомните имя элемента в палитре (**Имя**, обычно `ГлавныйБухгалтер`). Его использует код видимости.
4. Выделите поле `ТипОрганизации` → события → **ПриИзменении** → лупа. Вставьте вызов процедуры видимости (см. ниже).
5. Модуль формы — целиком:

```
&НаСервере
Процедура ПриСозданииНаСервере(Отказ, СтандартнаяОбработка)
	УстановитьВидимостьГлавногоБухгалтера();
КонецПроцедуры

&НаКлиенте
Процедура ТипОрганизацииПриИзменении(Элемент)
	УстановитьВидимостьГлавногоБухгалтера();
КонецПроцедуры

&НаСервере
Процедура УстановитьВидимостьГлавногоБухгалтера()
	ЭтоЮрЛицо = Объект.ТипОрганизации = Перечисления.ТипыОрганизаций.ЮридическоеЛицо;
	Элементы.ГлавныйБухгалтер.Видимость = ЭтоЮрЛицо;
КонецПроцедуры
```

Если `ПриСозданииНаСервере` уже есть пустая — допишите в неё вызов, не создавайте вторую.

6. Форма списка: **Формы** → **Добавить** → форма списка `ФормаСписка`. Колонки: Тип организации, Наименование, ИНН, Код (порядок как в макете). Назначьте основной формой списка.

Проверка в предприятии: откройте организацию, переключите тип на ИП — главный бухгалтер исчезает. Верните юрлицо.

## 2.2. Породы питомцев

### Форма элемента

1. Справочник `ПородыПитомцев` → Формы → Добавить → форма элемента.
2. Поля: Код; ВидПитомца (**Вид** = поле переключателя); Порода (это Наименование); Родитель.
3. Событие `ВидПитомца` → **ПриИзменении**:

```
&НаКлиенте
Процедура ВидПитомцаПриИзменении(Элемент)
	Если Объект.ВидПитомца = ПредопределенноеЗначение("Перечисление.ВидыПитомцев.Кошка") Тогда
		Объект.Родитель = ПредопределенноеЗначение("Справочник.ПородыПитомцев.Кошки");
	ИначеЕсли Объект.ВидПитомца = ПредопределенноеЗначение("Перечисление.ВидыПитомцев.Собака") Тогда
		Объект.Родитель = ПредопределенноеЗначение("Справочник.ПородыПитомцев.Собаки");
	КонецЕсли;
КонецПроцедуры
```

### Форма списка

1. Добавить форму списка.
2. Колонки: Порода (наименование), Код, Вид питомца.
3. Выделите таблицу списка на форме → палитра → **Отображение** = `Дерево`.
4. Назначьте основной формой списка.

Проверка: список сразу деревом, без «Ещё → Режим просмотра».

## 2.3. Контрагенты

Форма элемента с **страницами** (вид группы Страницы): **Основное** и **Договоры**.

На странице Основное сверху: **ТипКонтрагента** — переключатель Клиент / Поставщик.

Дальше поля, которые зависят от типа (урок «видимость по условию»):

**Если Клиент**

- Код
- Наименование с синонимом **Ф.И.О. клиента** (можно менять заголовок элемента `Элементы.Наименование.Заголовок`)
- Контактный телефон
- Дата рождения клиента
- Пол
- Источник
- Таблица Питомцы: Вид, Порода, Кличка, Дата рождения
- Комментарий внизу (в макете спринта 2 комментарий под таблицей)

**Если Поставщик**

- Код
- Наименование
- Контактный телефон
- Основной договор
- Комментарий (большое поле)

Страница **Договоры**: таблица с отбором по владельцу. Добавьте на форму **таблицу** с типом `ДинамическийСписок`, основная таблица `Справочник.ДоговорыКонтрагентов`, отбор `Владелец` = `Объект.Ссылка`. Список доступен после записи элемента.

Модуль (схема):

```
&НаСервере
Процедура ПриСозданииНаСервере(Отказ, СтандартнаяОбработка)
	НастроитьФормуПоТипу();
КонецПроцедуры

&НаКлиенте
Процедура ТипКонтрагентаПриИзменении(Элемент)
	НастроитьФормуПоТипу();
	Если Объект.ТипКонтрагента = ПредопределенноеЗначение("Перечисление.ТипыКонтрагентов.Клиент") Тогда
		Объект.Родитель = ПредопределенноеЗначение("Справочник.Контрагенты.Клиенты");
	Иначе
		Объект.Родитель = ПредопределенноеЗначение("Справочник.Контрагенты.Поставщики");
	КонецЕсли;
КонецПроцедуры

&НаСервере
Процедура НастроитьФормуПоТипу()
	ЭтоКлиент = Объект.ТипКонтрагента = Перечисления.ТипыКонтрагентов.Клиент;
	Элементы.ДатаРождения.Видимость = ЭтоКлиент;
	Элементы.Пол.Видимость = ЭтоКлиент;
	Элементы.Источник.Видимость = ЭтоКлиент;
	Элементы.Питомцы.Видимость = ЭтоКлиент;
	Элементы.ОсновнойДоговор.Видимость = Не ЭтоКлиент;
	Если ЭтоКлиент Тогда
		Элементы.Наименование.Заголовок = "Ф.И.О. клиента";
	Иначе
		Элементы.Наименование.Заголовок = "Наименование";
	КонецЕсли;
КонецПроцедуры
```

Форма списка: дерево, колонки Наименование, Код, Тип контрагента, Контактный тел., Дата рождения клиента, Пол, Договор, Источник, Комментарий.

## 2.4. Договоры

Форма элемента. **Наименование** — только просмотр.

Поля: Код, Наименование, Владелец, Номер договора, Дата заключения, Действует до, Бессрочный, Комментарий.

В макете дата заключения и «Действует до» стоят в одной строке.

```
&НаКлиенте
Процедура ПриОткрытии(Отказ)
	СформироватьНаименование();
	НастроитьСрок();
КонецПроцедуры

&НаКлиенте
Процедура НомерДоговораПриИзменении(Элемент)
	СформироватьНаименование();
КонецПроцедуры

&НаКлиенте
Процедура ДатаЗаключенияПриИзменении(Элемент)
	СформироватьНаименование();
КонецПроцедуры

&НаКлиенте
Процедура БессрочныйПриИзменении(Элемент)
	НастроитьСрок();
КонецПроцедуры

&НаКлиенте
Процедура СформироватьНаименование()
	Если ПустаяСтрока(Объект.НомерДоговора) Или Не ЗначениеЗаполнено(Объект.ДатаЗаключения) Тогда
		Возврат;
	КонецЕсли;
	Объект.Наименование = "№ " + Объект.НомерДоговора
		+ " от " + Формат(Объект.ДатаЗаключения, "ДФ=dd.MM.yyyy") + " г.";
КонецПроцедуры

&НаКлиенте
Процедура НастроитьСрок()
	Элементы.СрокДействия.Видимость = Не Объект.Бессрочный;
	Если Объект.Бессрочный Тогда
		Объект.СрокДействия = Дата(1, 1, 1);
	КонецЕсли;
КонецПроцедуры
```

Сделайте наименование недоступным: `Элементы.Наименование.ТолькоПросмотр = Истина` в `ПриСозданииНаСервере`.

Форма списка: Наименование, Владелец, Номер, даты.

При изменении типа можно подставлять группу Услуги / Товары / Материалы — по аналогии с породами.

## 2.6. Сотрудники

Форма элемента: Таб.№, Ф.И.О. (только просмотр), Фамилия, Имя, Отчество, Пол, Дата рождения, Должность, Контактный телефон.

```
&НаКлиенте
Процедура ФамилияПриИзменении(Элемент)
	СобратьФИО();
КонецПроцедуры

&НаКлиенте
Процедура ИмяПриИзменении(Элемент)
	СобратьФИО();
КонецПроцедуры

&НаКлиенте
Процедура ОтчествоПриИзменении(Элемент)
	СобратьФИО();
КонецПроцедуры

&НаКлиенте
Процедура СобратьФИО()
	Объект.Наименование = СокрЛП(Объект.Фамилия + " " + Объект.Имя + " " + Объект.Отчество);
КонецПроцедуры
```

`Элементы.Наименование.ТолькоПросмотр = Истина`.

Форма выбора (отдельная форма, имя `ФормаВыбора`): колонки Таб.№, Ф.И.О., Должность. Назначьте основной формой выбора.

Форма списка: Таб.№, Ф.И.О., Должность, Дата рождения, Контактный телефон.

## 2.7. Пользователи

Основная форма элемента — можно оставить сгенерированную: Идентификатор, Имя пользователя.

Форма списка **без** кнопок создания: в свойствах командной панели формы списка снимите **Автозаполнение**, оставьте только поиск. Либо у справочника отключите интерактивное добавление для роли (см. роли ниже) — ТЗ требует, чтобы у пользователей без права интерактивного создания **командная панель не содержала команд создания**. Это делается ролью, не удалением кнопки у администратора. Администратор с полными правами кнопки видит; оператор — нет.

## 2.8. Документ Запись клиента

Форма документа. Страницы: **Основное** и **Заказы клиентов**.

Шапка в две колонки, как макет:

- Номер | поле «От» = Дата
- Сотрудник | рядом нередактируемое поле **Должность** (реквизит формы `ДолжностьСотрудника`, заполняется при изменении сотрудника)
- Клиент | рядом **№ телефона** (реквизит формы `ТелефонКлиента`)
- Дата записи
- ТЧ Услуги: Услуга, Стоимость
- внизу Комментарий | Ответственный

```
&НаСервере
Процедура ПриСозданииНаСервере(Отказ, СтандартнаяОбработка)
	Если Не ЗначениеЗаполнено(Объект.Ссылка) Тогда
		Объект.Ответственный = ПараметрыСеанса.ТекущийПользователь;
	КонецЕсли;
	ЗаполнитьПоляПросмотра();
КонецПроцедуры

&НаСервере
Процедура ЗаполнитьПоляПросмотра()
	Если ЗначениеЗаполнено(Объект.Сотрудник) Тогда
		ДолжностьСотрудника = Объект.Сотрудник.Должность;
	Иначе
		ДолжностьСотрудника = Справочники.Должности.ПустаяСсылка();
	КонецЕсли;
	Если ЗначениеЗаполнено(Объект.Клиент) Тогда
		ТелефонКлиента = Объект.Клиент.КонтактныйТелефон;
	Иначе
		ТелефонКлиента = "";
	КонецЕсли;
КонецПроцедуры
```

Имена `ДолжностьСотрудника` и `ТелефонКлиента` добавьте как **реквизиты формы** (не документа), вид Поле надписи или поле ввода только просмотр.

Страница **Заказы клиентов**: таблица регистра накопления `ЗаказыКлиентов` с отбором по регистратору = текущий документ (после проведения). Типовой приём: поле формы тип `Таблица`, источник `РегистрНакопления.ЗаказыКлиентов.Обороты` или набор записей. Проще: команда перехода к движениям появится, если в свойствах документа включить **Регистр** в панели навигации формы. ТЗ: «ссылки на регистры вывести в панель навигации формы документа».

Как сделать: форма документа → **Командный интерфейс** (кнопка в редакторе формы) → **Панель навигации** → перетащите регистр **Заказы клиентов**.

Форма списка (журнал): Дата, Номер, Дата записи, Сотрудник, Клиент, Ответственный. Синоним формы списка можно задать `Журнал записи клиентов`.

Включите стандартную команду **Создать на основании** в списке.

### Движения записи клиента

Регистр **ЗаказыКлиентов** создайте до проведения (п. 2.11). В модуле объекта документа:

```
Процедура ОбработкаПроведения(Отказ, РежимПроведения)

	Движения.ЗаказыКлиентов.Записывать = Истина;

	Движение = Движения.ЗаказыКлиентов.Добавить();
	Движение.Период = Дата;
	Движение.Клиент = Клиент;
	Движение.ЗаписьКлиента = Ссылка;
	Движение.СуммаПлан = Услуги.Итог("Стоимость");
	Движение.СуммаФакт = 0;

КонецПроцедуры
```

Это уже не конструктор: регистра не было в спринте 1. Пишите вручную, как учили во втором спринте.

## 2.9. Реализация товаров и услуг

Форма документа. Страницы навигации/формы: **Основное**, и в панели навигации регистры **Заказы клиентов**, **Продажи**, **Товары на складах**.

Шапка: Номер, Дата, Клиент, Сотрудник, Склад (скрывается опцией), Основание.

Внутри Основное — страницы **Услуги** / **Товары** (как в макете).

Под таблицей: Итог по текущей ТЧ можно вывести свойством таблицы **Подвал** + поле итога. **Сумма документа** — только просмотр.

ТЗ: сумму документа считать **при записи**, не при каждом изменении строки.

Модуль объекта:

```
Процедура ПередЗаписью(Отказ, РежимЗаписи, РежимПроведения)
	СуммаДокумента = Услуги.Итог("Сумма") + Товары.Итог("Сумма");
КонецПроцедуры
```

В форме у поля СуммаДокумента: **ТолькоПросмотр** = Да.

В строке товаров при изменении количества или цены пересчитывайте **сумму строки** (это не сумма документа):

```
&НаКлиенте
Процедура ТоварыКоличествоПриИзменении(Элемент)
	ПересчитатьСуммуСтроки();
КонецПроцедуры

&НаКлиенте
Процедура ТоварыЦенаПриИзменении(Элемент)
	ПересчитатьСуммуСтроки();
КонецПроцедуры

&НаКлиенте
Процедура ПересчитатьСуммуСтроки()
	СтрокаТЧ = Элементы.Товары.ТекущиеДанные;
	Если СтрокаТЧ = Неопределено Тогда
		Возврат;
	КонецЕсли;
	СтрокаТЧ.Сумма = СтрокаТЧ.Количество * СтрокаТЧ.Цена;
КонецПроцедуры
```

Автор:

```
&НаСервере
Процедура ПриСозданииНаСервере(Отказ, СтандартнаяОбработка)
	Если Не ЗначениеЗаполнено(Объект.Ссылка) Тогда
		Объект.Ответственный = ПараметрыСеанса.ТекущийПользователь;
	КонецЕсли;
КонецПроцедуры
```

Форма списка: Дата, Номер, Клиент, Сотрудник, Сумма документа, Основание, Ответственный, Комментарий.

Кнопка **Печать** на форме.

### Оптимизация проведения (то, что проверяют особенно)

Откройте модуль объекта реализации. Конструктор оставил два цикла по ТЧ Товары. Замените на **один** обход товаров: в теле цикла сразу две записи — расход склада и оборот продаж. Затем отдельный цикл по услугам только в Продажи. Заказы клиентов — если заполнен Основание.

```
Процедура ОбработкаПроведения(Отказ, РежимПроведения)

	Движения.ТоварыНаСкладах.Записывать = Истина;
	Движения.Продажи.Записывать = Истина;
	Движения.ЗаказыКлиентов.Записывать = Истина;

	Для Каждого СтрокаТовары Из Товары Цикл

		ДвижениеСклад = Движения.ТоварыНаСкладах.Добавить();
		ДвижениеСклад.ВидДвижения = ВидДвиженияНакопления.Расход;
		ДвижениеСклад.Период = Дата;
		ДвижениеСклад.Номенклатура = СтрокаТовары.Товар;
		ДвижениеСклад.Склад = Склад;
		ДвижениеСклад.Количество = СтрокаТовары.Количество;

		ДвижениеПродажи = Движения.Продажи.Добавить();
		ДвижениеПродажи.Период = Дата;
		ДвижениеПродажи.Номенклатура = СтрокаТовары.Товар;
		ДвижениеПродажи.Сотрудник = Сотрудник;
		ДвижениеПродажи.Клиент = Клиент;
		ДвижениеПродажи.Сумма = СтрокаТовары.Сумма;

	КонецЦикла;

	Для Каждого СтрокаУслуги Из Услуги Цикл

		ДвижениеПродажи = Движения.Продажи.Добавить();
		ДвижениеПродажи.Период = Дата;
		ДвижениеПродажи.Номенклатура = СтрокаУслуги.Услуга;
		ДвижениеПродажи.Сотрудник = Сотрудник;
		ДвижениеПродажи.Клиент = Клиент;
		ДвижениеПродажи.Сумма = СтрокаУслуги.Сумма;

	КонецЦикла;

	Если ЗначениеЗаполнено(Основание) Тогда
		ДвижениеЗаказ = Движения.ЗаказыКлиентов.Добавить();
		ДвижениеЗаказ.Период = Дата;
		ДвижениеЗаказ.Клиент = Клиент;
		ДвижениеЗаказ.ЗаписьКлиента = Основание;
		ДвижениеЗаказ.СуммаПлан = 0;
		ДвижениеЗаказ.СуммаФакт = Услуги.Итог("Сумма");
	КонецЕсли;

КонецПроцедуры
```

Если опция складов выключена, не пишите складской регистр (оберните первый блок `Если Константы.ИспользоватьСклады.Получить() Тогда` или проверяйте функциональную опцию).

Печать: пустые ТЧ не выводить — см. код в спринте 1. Внешний вид макета как в ТЗ: две отдельные таблицы услуг и товаров, внизу сумма и ответственный.

## 2.12. Параметр сеанса и автосоздание пользователя

Это центральная методика спринта 2. Делайте **как в учебнике**, не изобретайте REST-логин.

1. **Параметры сеанса** → `ТекущийПользователь`, тип `СправочникСсылка.Пользователи`.
2. Общий модуль `Пользователи` (сервер, вызов сервера, привилегированный — как в уроке).
3. Модуль сеанса конфигурации (корень конфигурации → **Модуль сеанса**):

```
Процедура УстановкаПараметровСеанса(ТребуемыеПараметры)
	Пользователи.УстановитьПараметрыСеанса();
КонецПроцедуры
```

В общем модуле логика «найти по идентификатору пользователя ИБ, если нет — создать элемент справочника»:

```
Процедура УстановитьПараметрыСеанса() Экспорт

	ПользовательИБ = ПользователиИнформационнойБазы.ТекущийПользователь();
	Идентификатор = Строка(ПользовательИБ.УникальныйИдентификатор);

	Запрос = Новый Запрос;
	Запрос.Текст =
		"ВЫБРАТЬ
		|	Пользователи.Ссылка КАК Ссылка
		|ИЗ
		|	Справочник.Пользователи КАК Пользователи
		|ГДЕ
		|	Пользователи.ИдентификаторПользователяИБ = &Идентификатор";
	Запрос.УстановитьПараметр("Идентификатор", Идентификатор);

	Результат = Запрос.Выполнить();
	Если Результат.Пустой() Тогда
		Элемент = Справочники.Пользователи.СоздатьЭлемент();
		Элемент.Наименование = ПользовательИБ.ПолноеИмя;
		Элемент.ИдентификаторПользователяИБ = Идентификатор;
		Элемент.Записать();
		ПараметрыСеанса.ТекущийПользователь = Элемент.Ссылка;
	Иначе
		Выборка = Результат.Выбрать();
		Выборка.Следующий();
		ПараметрыСеанса.ТекущийПользователь = Выборка.Ссылка;
	КонецЕсли;

КонецПроцедуры
```

Пользователей информационной базы заводят в Конфигураторе: **Администрирование** → **Пользователи**. Создайте:

| Имя (для входа) | Полное имя | Роль |
| --- | --- | --- |
| Мазаева | Мазаева Ангелина | ПолныеПрава |
| Оператор | Оператор салона | ПолныеПраваБезДобавленияПользователей |

При первом входе элемент справочника **Пользователи** появится сам.

## 2.15. Как самому проверить, что усвоены приёмы курса

Ревьюер смотрит не на «похожесть кнопок», а на приёмы:

1. Переключатель вместо выпадающего списка там, где в макете две кнопки.
2. Видимость элементов, а не удаление реквизитов.
3. Наименование договора и ФИО **собираются программно**, поле недоступно.
4. Сумма реализации в `ПередЗаписью`, не в каждом `ПриИзменении` таблицы.
5. Один цикл по товарам для двух регистров.
6. Движения заказов у реализации **только при основании**.
7. Печать без пустых таблиц.
8. Параметр сеанса + привилегированный общий модуль, а не ручной выбор автора.
9. Вторая роль без интерактивного создания пользователей.
10. Объекты разложены по подсистемам, начальная страница — журнал записей.

Если какой-то пункт «работает, но сделан иначе, чем в уроке» — переделайте по уроку. Это и есть критерий «студент усвоил материал».
