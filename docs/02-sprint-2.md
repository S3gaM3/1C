Продолжайте **в той же** новой базе, которую создали в файле 00. Платформа **8.3.27.2130**, Конфигуратор. Объекты из файла 01 уже должны быть в дереве, в модуле реализации — код конструктора.

## 2.0. Общий рецепт: как создать форму (повторяйте для каждого объекта)

### Форма элемента справочника

1. В дереве конфигурации раскройте справочник (например `Организации`), нажав плюсик слева от имени.
2. Найдите внутри ветку **Формы**.
3. Нажмите **правую кнопку мыши** по ветке **Формы**.
4. Выберите **Добавить**.
5. Откроется мастер. Тип формы: **Форма элемента справочника**. Имя оставьте `ФормаЭлемента`.
6. Если мастер предлагает отметить реквизиты галочками — отметьте нужные и нажмите **Готово**. Если открылась пустая форма — перетащите реквизиты из окна **Реквизиты** (слева в редакторе формы, дерево `Объект`) на холст.
7. Расположите поля сверху вниз как на макете учебного задания: захватите элемент мышью в дереве элементов формы (обычно слева или справа список `Элементы`) и перетащите выше или ниже.
8. Чтобы сделать переключатель: один раз щёлкните поле на форме → палитра свойств **элемента** (смотрите заголовок палитры: там должно быть имя элемента, не имя справочника) → свойство **Вид** = `Поле переключателя`. Для перечисления значения подтянутся сами.
9. Назначить форму основной: закройте форму (крестик), согласитесь сохранить. В окне справочника откройте вкладку **Формы**. В поле **Основная форма элемента** нажмите лупу и выберите вашу форму.

### Событие поля (чтобы писать код)

1. Выделите поле на форме одним щелчком.
2. Палитра свойств элемента → прокрутите до группы **События**.
3. У нужного события (например **ПриИзменении**) нажмите лупу (увеличительное стекло).
4. Платформа создаст процедуру в модуле формы. Пишите код **внутрь** этой процедуры, не создавайте вторую с тем же именем.

### Модуль формы

В редакторе формы найдите кнопку **Модуль** (часто внизу или на панели инструментов). Клиентские процедуры помечайте директивой `&НаКлиенте`, серверные — `&НаСервере`.

### Форма списка

1. Правая кнопка мыши по ветке **Формы** → **Добавить**.
2. Тип мастера: **Форма списка**. Имя оставьте `ФормаСписка`.
3. В списке колонок оставьте те, что на макете. Лишнюю колонку удалите: правая кнопка мыши по колонке в дереве элементов → **Удалить**. Либо выделите таблицу `Список` и настройте колонки в её свойствах.
4. Основная форма списка: вкладка **Формы** справочника → поле **Основная форма списка** → лупа → ваша форма.
5. Для дерева: выделите таблицу списка на форме → палитра свойств → **Отображение** = `Дерево`.

### Форма документа

Так же, тип мастера **Форма документа**. Стандартные кнопки «Провести и закрыть», «Записать», «Провести» появятся сами, если не снимали командную панель.

После каждой формы сохраните конфигурацию и обновите базу данных: меню **Конфигурация** → **Сохранить конфигурацию** (клавиши Ctrl и S), затем **Конфигурация** → **Обновить конфигурацию базы данных** (клавиша F7), в окне реорганизации нажмите **Принять**.

## 2.1. Форма элемента Организации

1. Справочник `Организации` → ветка **Формы** → правая кнопка мыши → **Добавить** → форма элемента, имя `ФормаЭлемента`.
2. На холсте сверху вниз (перетащите или оставьте из мастера):

   1. `ТипОрганизации` — палитра элемента → **Вид** = **Поле переключателя**
   2. `Код`
   3. `Наименование`
   4. `ИНН`
   5. `Руководитель`
   6. `ДолжностьРуководителя`
   7. `ГлавныйБухгалтер`

3. Полю `ГлавныйБухгалтер` запомните имя элемента в палитре (**Имя**, обычно `ГлавныйБухгалтер`). Его использует код видимости. Если имя другое — либо переименуйте элемент в `ГлавныйБухгалтер`, либо поправьте имя в коде ниже.
4. Выделите поле `ТипОрганизации` → события → **ПриИзменении** → лупа. Платформа создаст процедуру. Вставьте в модуль формы целиком текст ниже.
5. Модуль формы — целиком:

```
&НаСервере
Процедура ПриСозданииНаСервере(Отказ, СтандартнаяОбработка)
	УстановитьВидимостьГлавногоБухгалтера();
КонецПроцедуры

&НаКлиенте
Процедура ТипОрганизацииПриИзменении(Элемент)
	УстановитьВидимостьГлавногоБухгалтера();
КонецПроцедуры

&НаСервере
Процедура УстановитьВидимостьГлавногоБухгалтера()
	ЭтоЮрЛицо = Объект.ТипОрганизации = Перечисления.ТипыОрганизаций.ЮридическоеЛицо;
	Элементы.ГлавныйБухгалтер.Видимость = ЭтоЮрЛицо;
КонецПроцедуры
```

Если процедура `ПриСозданииНаСервере` уже есть пустая — допишите в неё вызов, не создавайте вторую.

6. Форма списка: **Формы** → правая кнопка мыши → **Добавить** → форма списка `ФормаСписка`. Колонки: Тип организации, Наименование, ИНН, Код (порядок как в макете). Назначьте основной формой списка на вкладке **Формы** справочника.

Проверка в предприятии: откройте организацию, переключите тип на ИП — главный бухгалтер исчезает. Верните юридическое лицо.

## 2.2. Породы питомцев

### Форма элемента

1. Справочник `ПородыПитомцев` → Формы → правая кнопка мыши → Добавить → форма элемента.
2. Поля сверху вниз: Код; ВидПитомца (**Вид** элемента = поле переключателя); Порода (это стандартное Наименование); Родитель.
3. Выделите поле `ВидПитомца` → события → **ПриИзменении** → лупа. Вставьте:

```
&НаКлиенте
Процедура ВидПитомцаПриИзменении(Элемент)
	Если Объект.ВидПитомца = ПредопределенноеЗначение("Перечисление.ВидыПитомцев.Кошка") Тогда
		Объект.Родитель = ПредопределенноеЗначение("Справочник.ПородыПитомцев.Кошки");
	ИначеЕсли Объект.ВидПитомца = ПредопределенноеЗначение("Перечисление.ВидыПитомцев.Собака") Тогда
		Объект.Родитель = ПредопределенноеЗначение("Справочник.ПородыПитомцев.Собаки");
	КонецЕсли;
КонецПроцедуры
```

### Форма списка

1. Правая кнопка мыши по **Формы** → Добавить → форма списка.
2. Колонки: Порода (наименование), Код, Вид питомца.
3. Выделите таблицу списка на форме одним щелчком → палитра → **Отображение** = `Дерево`.
4. На вкладке **Формы** справочника назначьте эту форму основной формой списка.

Проверка: список сразу деревом, без «Ещё → Режим просмотра».

## 2.3. Контрагенты

Форма элемента с **страницами**. Страницы — это группа элементов, у которой свойство **Вид** = `Страницы`. Внутри две страницы: **Основное** и **Договоры**.

Как сделать страницы:

1. В редакторе формы в дереве элементов нажмите **Добавить** → **Группа** → вид **Страницы**.
2. Внутри появятся или добавьте две группы вида **Страница**. Имена: `СтраницаОсновное` (заголовок «Основное») и `СтраницаДоговоры` (заголовок «Договоры»).
3. Перетащите поля на нужную страницу.

На странице Основное сверху: **ТипКонтрагента** — переключатель Клиент / Поставщик (свойство **Вид** элемента = Поле переключателя).

Дальше поля, которые зависят от типа (урок «видимость по условию»):

**Если тип = Клиент**, должны быть видны:

- Код
- Наименование с заголовком **Ф.И.О. клиента** (заголовок меняет код: `Элементы.Наименование.Заголовок`)
- Контактный телефон
- Дата рождения клиента
- Пол
- Источник
- Таблица Питомцы: колонки Вид, Порода, Кличка, Дата рождения
- Комментарий внизу (в макете спринта 2 комментарий под таблицей)

**Если тип = Поставщик**, должны быть видны:

- Код
- Наименование (заголовок «Наименование»)
- Контактный телефон
- Основной договор
- Комментарий (большое поле)

Поля клиента при типе Поставщик скрываются кодом ниже, поля поставщика — наоборот. Реквизиты из справочника **не удаляйте**.

Страница **Договоры**: таблица с отбором по владельцу. Добавьте на форму **таблицу**. В свойствах таблицы:

1. Создайте реквизит формы (не справочника): в окне **Реквизиты** правая кнопка мыши → **Добавить** → имя `ДоговорыКонтрагента`, тип **ДинамическийСписок**.
2. У динамического списка свойство **Основная таблица** = `Справочник.ДоговорыКонтрагентов`.
3. Отбор: владелец = `Объект.Ссылка`. Список доступен после записи элемента (пока контрагент не записан, ссылки нет).

Модуль формы (скопируйте целиком; имена элементов `ДатаРождения`, `Пол`, `Источник`, `Питомцы`, `ОсновнойДоговор`, `Наименование` должны совпасть с именами на форме):

```
&НаСервере
Процедура ПриСозданииНаСервере(Отказ, СтандартнаяОбработка)
	НастроитьФормуПоТипу();
КонецПроцедуры

&НаКлиенте
Процедура ТипКонтрагентаПриИзменении(Элемент)
	НастроитьФормуПоТипу();
	Если Объект.ТипКонтрагента = ПредопределенноеЗначение("Перечисление.ТипыКонтрагентов.Клиент") Тогда
		Объект.Родитель = ПредопределенноеЗначение("Справочник.Контрагенты.Клиенты");
	Иначе
		Объект.Родитель = ПредопределенноеЗначение("Справочник.Контрагенты.Поставщики");
	КонецЕсли;
КонецПроцедуры

&НаСервере
Процедура НастроитьФормуПоТипу()
	ЭтоКлиент = Объект.ТипКонтрагента = Перечисления.ТипыКонтрагентов.Клиент;
	Элементы.ДатаРождения.Видимость = ЭтоКлиент;
	Элементы.Пол.Видимость = ЭтоКлиент;
	Элементы.Источник.Видимость = ЭтоКлиент;
	Элементы.Питомцы.Видимость = ЭтоКлиент;
	Элементы.ОсновнойДоговор.Видимость = Не ЭтоКлиент;
	Если ЭтоКлиент Тогда
		Элементы.Наименование.Заголовок = "Ф.И.О. клиента";
	Иначе
		Элементы.Наименование.Заголовок = "Наименование";
	КонецЕсли;
КонецПроцедуры
```

Форма списка: отображение **Дерево**, колонки Наименование, Код, Тип контрагента, Контактный телефон, Дата рождения клиента, Пол, Договор, Источник, Комментарий. Назначьте основной формой списка.

## 2.4. Договоры

1. Справочник `ДоговорыКонтрагентов` → Формы → правая кнопка мыши → Добавить → форма элемента.
2. Поле **Наименование** сделайте только для просмотра: выделите элемент на форме → палитра → **ТолькоПросмотр** = Да. Либо в коде `ПриСозданииНаСервере` строка `Элементы.Наименование.ТолькоПросмотр = Истина`.

Поля сверху вниз: Код, Наименование, Владелец, Номер договора, Дата заключения, Действует до, Бессрочный, Комментарий.

В макете дата заключения и «Действует до» стоят в одной строке. Для этого создайте группу вида **Обычная группа**, группировка **Горизонтальная**, перетащите в неё оба поля.

События полей (лупа у **ПриИзменении**):

- `НомерДоговора` → вызывает `СформироватьНаименование`
- `ДатаЗаключения` → вызывает `СформироватьНаименование`
- `Бессрочный` → вызывает `НастроитьСрок`

Модуль формы:

```
&НаКлиенте
Процедура ПриОткрытии(Отказ)
	СформироватьНаименование();
	НастроитьСрок();
КонецПроцедуры

&НаКлиенте
Процедура НомерДоговораПриИзменении(Элемент)
	СформироватьНаименование();
КонецПроцедуры

&НаКлиенте
Процедура ДатаЗаключенияПриИзменении(Элемент)
	СформироватьНаименование();
КонецПроцедуры

&НаКлиенте
Процедура БессрочныйПриИзменении(Элемент)
	НастроитьСрок();
КонецПроцедуры

&НаКлиенте
Процедура СформироватьНаименование()
	Если ПустаяСтрока(Объект.НомерДоговора) Или Не ЗначениеЗаполнено(Объект.ДатаЗаключения) Тогда
		Возврат;
	КонецЕсли;
	Объект.Наименование = "№ " + Объект.НомерДоговора
		+ " от " + Формат(Объект.ДатаЗаключения, "ДФ=dd.MM.yyyy") + " г.";
КонецПроцедуры

&НаКлиенте
Процедура НастроитьСрок()
	Элементы.СрокДействия.Видимость = Не Объект.Бессрочный;
	Если Объект.Бессрочный Тогда
		Объект.СрокДействия = Дата(1, 1, 1);
	КонецЕсли;
КонецПроцедуры
```

Имя элемента поля «Действует до» должно быть `СрокДействия` (как имя реквизита). Если мастер назвал иначе — переименуйте элемент.

Форма списка: колонки Наименование, Владелец, Номер, даты. Назначьте основной формой списка.

## 2.5. Номенклатура

Форма элемента по макету: Код, Тип номенклатуры (переключатель), Наименование, Родитель.

Форма списка: наименование, код, тип.

При изменении типа можно подставлять группу Услуги / Товары / Материалы — по аналогии с породами. Событие `ТипНоменклатуры` → **ПриИзменении**:

```
&НаКлиенте
Процедура ТипНоменклатурыПриИзменении(Элемент)
	Если Объект.ТипНоменклатуры = ПредопределенноеЗначение("Перечисление.ТипыНоменклатуры.Услуга") Тогда
		Объект.Родитель = ПредопределенноеЗначение("Справочник.Номенклатура.Услуги");
	ИначеЕсли Объект.ТипНоменклатуры = ПредопределенноеЗначение("Перечисление.ТипыНоменклатуры.Товар") Тогда
		Объект.Родитель = ПредопределенноеЗначение("Справочник.Номенклатура.Товары");
	ИначеЕсли Объект.ТипНоменклатуры = ПредопределенноеЗначение("Перечисление.ТипыНоменклатуры.Материал") Тогда
		Объект.Родитель = ПредопределенноеЗначение("Справочник.Номенклатура.Материалы");
	КонецЕсли;
КонецПроцедуры
```

## 2.6. Сотрудники

Форма элемента: Таб.№, Ф.И.О. (только просмотр), Фамилия, Имя, Отчество, Пол, Дата рождения, Должность, Контактный телефон.

Поле Ф.И.О. — это стандартное **Наименование**. Выделите его → **ТолькоПросмотр** = Да. Либо в `ПриСозданииНаСервере`: `Элементы.Наименование.ТолькоПросмотр = Истина`.

События **ПриИзменении** у полей Фамилия, Имя, Отчество:

```
&НаКлиенте
Процедура ФамилияПриИзменении(Элемент)
	СобратьФИО();
КонецПроцедуры

&НаКлиенте
Процедура ИмяПриИзменении(Элемент)
	СобратьФИО();
КонецПроцедуры

&НаКлиенте
Процедура ОтчествоПриИзменении(Элемент)
	СобратьФИО();
КонецПроцедуры

&НаКлиенте
Процедура СобратьФИО()
	Объект.Наименование = СокрЛП(Объект.Фамилия + " " + Объект.Имя + " " + Объект.Отчество);
КонецПроцедуры
```

Форма выбора (отдельная форма, имя `ФормаВыбора`):

1. Правая кнопка мыши по **Формы** → Добавить → тип **Форма выбора**.
2. Колонки: Таб.№, Ф.И.О., Должность.
3. На вкладке **Формы** справочника поле **Основная форма выбора** = эта форма.

Форма списка: колонки Таб.№, Ф.И.О., Должность, Дата рождения, Контактный телефон. Назначьте основной формой списка.

## 2.7. Пользователи

Основная форма элемента — можно оставить сгенерированную: Идентификатор, Имя пользователя.

## 2.8. Документ Запись клиента

### Форма документа

1. Документ `ЗаписьКлиента` → Формы → правая кнопка мыши → Добавить → тип **Форма документа**, имя `ФормаДокумента`.
2. Сделайте страницы: группа вида **Страницы**, две страницы **Основное** и **Заказы клиентов**.

Шапка в две колонки, как макет. Для двух колонок создайте обычную группу с горизонтальной группировкой.

- Номер | поле «От» = Дата (стандартные реквизиты документа)
- Сотрудник | рядом нередактируемое поле **Должность**
- Клиент | рядом **№ телефона**
- Дата записи
- табличная часть Услуги: колонки Услуга, Стоимость
- внизу Комментарий | Ответственный

Поля **Должность** и **№ телефона** — это **не** реквизиты документа. Их добавляют как реквизиты формы:

1. В редакторе формы окно **Реквизиты** (не дерево конфигурации).
2. Правая кнопка мыши по корню реквизитов формы → **Добавить**.
3. Первый реквизит формы: имя `ДолжностьСотрудника`, тип ссылка на справочник `Должности`.
4. Второй: имя `ТелефонКлиента`, тип Строка, длина 20.
5. Перетащите их на форму рядом с Сотрудник и Клиент. Свойство **ТолькоПросмотр** = Да. Вид можно поставить **Поле надписи** или поле ввода только просмотр.

Модуль формы (подстановку ответственного делайте после пункта 2.12, когда появится параметр сеанса; до этого строку с `ПараметрыСеанса` можно временно не вставлять):

```
&НаСервере
Процедура ПриСозданииНаСервере(Отказ, СтандартнаяОбработка)
	Если Не ЗначениеЗаполнено(Объект.Ссылка) Тогда
		Объект.Ответственный = ПараметрыСеанса.ТекущийПользователь;
	КонецЕсли;
	ЗаполнитьПоляПросмотра();
КонецПроцедуры

&НаСервере
Процедура ЗаполнитьПоляПросмотра()
	Если ЗначениеЗаполнено(Объект.Сотрудник) Тогда
		ДолжностьСотрудника = Объект.Сотрудник.Должность;
	Иначе
		ДолжностьСотрудника = Справочники.Должности.ПустаяСсылка();
	КонецЕсли;
	Если ЗначениеЗаполнено(Объект.Клиент) Тогда
		ТелефонКлиента = Объект.Клиент.КонтактныйТелефон;
	Иначе
		ТелефонКлиента = "";
	КонецЕсли;
КонецПроцедуры
```

Добавьте события **ПриИзменении** у полей Сотрудник и Клиент, внутри вызовите `ЗаполнитьПоляПросмотра();`. Если вызов с клиента не компилируется, сделайте клиентскую обёртку, которая вызывает серверную процедуру.

Страница **Заказы клиентов**: ссылка на регистр накопления `ЗаказыКлиентов` с отбором по регистратору = текущий документ (после проведения). Учебное задание: «ссылки на регистры вывести в панель навигации формы документа».

Как сделать:

1. В редакторе формы нажмите кнопку **Командный интерфейс** (на панели редактора формы).
2. Слева найдите **Панель навигации**.
3. Перетащите регистр **Заказы клиентов** в панель навигации формы. Регистр должен быть в движениях документа (после пункта 2.11).

Форма списка (журнал): колонки Дата, Номер, Дата записи, Сотрудник, Клиент, Ответственный. Синоним формы списка можно задать `Журнал записи клиентов` (свойство формы **Синоним** или заголовок).

Включите стандартную команду **Создать на основании** в списке: командный интерфейс формы списка → команда ввода на основании реализации.

### Движения записи клиента

Регистр **ЗаказыКлиентов** создайте до проведения (пункт 2.11). Затем откройте модуль объекта документа: правая кнопка мыши по документу `ЗаписьКлиента` в дереве → **Открыть модуль объекта**. Вставьте:

```
Процедура ОбработкаПроведения(Отказ, РежимПроведения)

	Движения.ЗаказыКлиентов.Записывать = Истина;

	Движение = Движения.ЗаказыКлиентов.Добавить();
	Движение.Период = Дата;
	Движение.Клиент = Клиент;
	Движение.ЗаписьКлиента = Ссылка;
	Движение.СуммаПлан = Услуги.Итог("Стоимость");
	Движение.СуммаФакт = 0;

КонецПроцедуры
```

Это уже не конструктор: регистра не было в спринте 1. Пишите вручную, как учили во втором спринте. Сохраните конфигурацию и обновите базу данных.

## 2.9. Реализация товаров и услуг

### Форма документа

1. Документ `РеализацияТоваровИУслуг` → Формы → Добавить → форма документа.
2. Страницы формы: **Основное**. В панели навигации формы (кнопка **Командный интерфейс**) перетащите регистры **Заказы клиентов**, **Продажи**, **Товары на складах**.

Шапка: Номер, Дата, Клиент, Сотрудник, Склад (скроется функциональной опцией, если снят флажок складов), Основание.

Внутри Основное — ещё одни страницы **Услуги** / **Товары** (как в макете). Группа вида Страницы, две страницы, на каждую перетащите соответствующую таблицу.

Под таблицей: итог по текущей табличной части можно вывести свойством таблицы **Подвал** = Да и добавить поле итога. Поле **Сумма документа** — только просмотр.

Учебное задание: сумму документа считать **при записи**, не при каждом изменении строки.

Откройте модуль объекта реализации: правая кнопка мыши по документу → **Открыть модуль объекта**. Добавьте (рядом с проведением, не внутри него):

```
Процедура ПередЗаписью(Отказ, РежимЗаписи, РежимПроведения)
	СуммаДокумента = Услуги.Итог("Сумма") + Товары.Итог("Сумма");
КонецПроцедуры
```

В форме у поля СуммаДокумента: **ТолькоПросмотр** = Да.

В строке товаров при изменении количества или цены пересчитывайте **сумму строки** (это не сумма документа). Выделите колонку Количество таблицы Товары → событие **ПриИзменении**. То же для колонки Цена.

```
&НаКлиенте
Процедура ТоварыКоличествоПриИзменении(Элемент)
	ПересчитатьСуммуСтроки();
КонецПроцедуры

&НаКлиенте
Процедура ТоварыЦенаПриИзменении(Элемент)
	ПересчитатьСуммуСтроки();
КонецПроцедуры

&НаКлиенте
Процедура ПересчитатьСуммуСтроки()
	СтрокаТЧ = Элементы.Товары.ТекущиеДанные;
	Если СтрокаТЧ = Неопределено Тогда
		Возврат;
	КонецЕсли;
	СтрокаТЧ.Сумма = СтрокаТЧ.Количество * СтрокаТЧ.Цена;
КонецПроцедуры
```

Имя `СтрокаТЧ` в коде не переименовывайте, если копируете как есть. Это служебное имя переменной.

Автор документа из параметра сеанса (после пункта 2.12):

```
&НаСервере
Процедура ПриСозданииНаСервере(Отказ, СтандартнаяОбработка)
	Если Не ЗначениеЗаполнено(Объект.Ссылка) Тогда
		Объект.Ответственный = ПараметрыСеанса.ТекущийПользователь;
	КонецЕсли;
КонецПроцедуры
```

Форма списка: Дата, Номер, Клиент, Сотрудник, Сумма документа, Основание, Ответственный, Комментарий.

Кнопка **Печать** на форме: если команду документа уже создали в спринте 1, в редакторе формы откройте **Командный интерфейс** и перетащите команду **Печать** на командную панель формы.

### Оптимизация проведения (обязательно для сдачи спринта 2)

Конструктор из пункта 1.17 оставил **два** цикла по табличной части Товары. Ревьюер спринта 2 ищет **один** обход товаров: в теле цикла сразу две записи — расход склада и оборот продаж. Затем отдельный цикл по услугам только в регистр Продажи. Заказы клиентов — если заполнен Основание.

Комментарии конструктора после этой замены пропадут — так и нужно.

Старую процедуру `ОбработкаПроведения` целиком замените на эту:

```
Процедура ОбработкаПроведения(Отказ, РежимПроведения)

	Движения.ТоварыНаСкладах.Записывать = Истина;
	Движения.Продажи.Записывать = Истина;
	Движения.ЗаказыКлиентов.Записывать = Истина;

	Для Каждого СтрокаТовары Из Товары Цикл

		ДвижениеСклад = Движения.ТоварыНаСкладах.Добавить();
		ДвижениеСклад.ВидДвижения = ВидДвиженияНакопления.Расход;
		ДвижениеСклад.Период = Дата;
		ДвижениеСклад.Номенклатура = СтрокаТовары.Товар;
		ДвижениеСклад.Склад = Склад;
		ДвижениеСклад.Количество = СтрокаТовары.Количество;

		ДвижениеПродажи = Движения.Продажи.Добавить();
		ДвижениеПродажи.Период = Дата;
		ДвижениеПродажи.Номенклатура = СтрокаТовары.Товар;
		ДвижениеПродажи.Сотрудник = Сотрудник;
		ДвижениеПродажи.Клиент = Клиент;
		ДвижениеПродажи.Сумма = СтрокаТовары.Сумма;

	КонецЦикла;

	Для Каждого СтрокаУслуги Из Услуги Цикл

		ДвижениеПродажи = Движения.Продажи.Добавить();
		ДвижениеПродажи.Период = Дата;
		ДвижениеПродажи.Номенклатура = СтрокаУслуги.Услуга;
		ДвижениеПродажи.Сотрудник = Сотрудник;
		ДвижениеПродажи.Клиент = Клиент;
		ДвижениеПродажи.Сумма = СтрокаУслуги.Сумма;

	КонецЦикла;

	Если ЗначениеЗаполнено(Основание) Тогда
		ДвижениеЗаказ = Движения.ЗаказыКлиентов.Добавить();
		ДвижениеЗаказ.Период = Дата;
		ДвижениеЗаказ.Клиент = Клиент;
		ДвижениеЗаказ.ЗаписьКлиента = Основание;
		ДвижениеЗаказ.СуммаПлан = 0;
		ДвижениеЗаказ.СуммаФакт = Услуги.Итог("Сумма");
	КонецЕсли;

КонецПроцедуры
```

Если опция складов выключена, не пишите складской регистр. Оберните блок склада так:

```
	Если Константы.ИспользоватьСклады.Получить() Тогда
		// здесь создание ДвижениеСклад, как выше
	КонецЕсли;
```

Печать: пустые табличные части не выводить — код уже есть в спринте 1 (`Если Документ.Услуги.Количество() > 0`). Внешний вид макета как в учебном задании: две отдельные таблицы услуг и товаров, внизу сумма и ответственный.

## 2.10. Поступление товаров

Форма документа. Расположение полей:

- Номер | Дата
- Номер входящего документа | Дата входящего документа
- Поставщик | Договор
- Склад
- табличная часть с колонками: Номенклатура, **Тип номенклатуры**, Количество, Цена, Сумма
- подвал с итогом
- Сумма документа только просмотр
- Комментарий | Ответственный

Колонка **Тип номенклатуры** — не новый реквизит табличной части. Это поле только просмотр, путь к данным: `Товары.Товар.ТипНоменклатуры`. Как добавить:

1. Выделите таблицу Товары на форме.
2. Внутри таблицы добавьте поле.
3. В свойствах поля **Путь к данным** укажите `Объект.Товары.Товар.ТипНоменклатуры` (точный путь подскажет лупа выбора).
4. **ТолькоПросмотр** = Да.

Сумму документа считайте автоматически. Учебное задание здесь не запрещает считать сразу; достаточно процедуры `ПередЗаписью` как у реализации:

```
Процедура ПередЗаписью(Отказ, РежимЗаписи, РежимПроведения)
	СуммаДокумента = Товары.Итог("Сумма");
КонецПроцедуры
```

В строке Количество × Цена = Сумма — те же клиентские процедуры, что у реализации, только таблица поступления.

Панель навигации формы: регистр **Товары на складах** (командный интерфейс формы).

Форма списка: Дата, Номер, Дата входящая, Номер входящий, Поставщик, Договор, Сумма документа, Склад.

Автор — из параметра сеанса при создании (как у записи клиента).

Проведение оставьте от конструктора спринта 1 (приход по табличной части Товары). Оптимизировать один цикл здесь не требовали.

## 2.12. Параметр сеанса и автосоздание пользователя

Это центральная методика спринта 2. Делайте **как в учебнике**, не изобретайте вход через другие системы.

### Шаг A. Параметр сеанса

1. В дереве раскройте ветку **Общие**.
2. Найдите **Параметры сеанса**.
3. Правая кнопка мыши по **Параметры сеанса** → **Добавить**.
4. **Имя:** `ТекущийПользователь`.
5. **Синоним:** `Текущий пользователь`.
6. **Тип:** кнопка T → слева `СправочникСсылка` → справа `Пользователи` → ОК.

### Шаг B. Общий модуль

1. Ветка **Общие** → **Общие модули** → правая кнопка мыши → **Добавить**.
2. **Имя:** `Пользователи`.
3. В палитре свойств модуля поставьте флажки, как на уроке: **Сервер**, **Вызов сервера**, **Привилегированный**. Клиентский флажок не нужен.

Откройте модуль (двойной щелчок или кнопка открытия) и вставьте:

```
Процедура УстановитьПараметрыСеанса() Экспорт

	ПользовательИБ = ПользователиИнформационнойБазы.ТекущийПользователь();
	Идентификатор = Строка(ПользовательИБ.УникальныйИдентификатор);

	Запрос = Новый Запрос;
	Запрос.Текст =
		"ВЫБРАТЬ
		|	Пользователи.Ссылка КАК Ссылка
		|ИЗ
		|	Справочник.Пользователи КАК Пользователи
		|ГДЕ
		|	Пользователи.ИдентификаторПользователяИБ = &Идентификатор";
	Запрос.УстановитьПараметр("Идентификатор", Идентификатор);

	Результат = Запрос.Выполнить();
	Если Результат.Пустой() Тогда
		Элемент = Справочники.Пользователи.СоздатьЭлемент();
		Элемент.Наименование = ПользовательИБ.ПолноеИмя;
		Элемент.ИдентификаторПользователяИБ = Идентификатор;
		Элемент.Записать();
		ПараметрыСеанса.ТекущийПользователь = Элемент.Ссылка;
	Иначе
		Выборка = Результат.Выбрать();
		Выборка.Следующий();
		ПараметрыСеанса.ТекущийПользователь = Выборка.Ссылка;
	КонецЕсли;

КонецПроцедуры
```

Логика простыми словами: взять текущего пользователя информационной базы, найти его в справочнике по идентификатору, если нет — создать элемент справочника и запомнить ссылку в параметре сеанса.

### Шаг C. Модуль сеанса конфигурации

1. Выделите корень `ГрумингСалон`.
2. Правая кнопка мыши → **Открыть модуль сеанса**. Если пункта нет: палитра свойств корня → свойство **Модуль сеанса** → лупа.
3. Вставьте:

```
Процедура УстановкаПараметровСеанса(ТребуемыеПараметры)
	Пользователи.УстановитьПараметрыСеанса();
КонецПроцедуры
```

Имя процедуры не меняйте: платформа вызывает именно `УстановкаПараметровСеанса`.

### Шаг D. Пользователи информационной базы

Пользователей информационной базы заводят в Конфигураторе, не в справочнике.

1. Меню **Администрирование** → **Пользователи**.
2. Нажмите **Добавить**.
3. Создайте двух пользователей:

| Имя (для входа) | Полное имя | Роль |
| --- | --- | --- |
| Мазаева | Мазаева Ангелина | ПолныеПрава |
| Оператор | Оператор салона | ПолныеПраваБезДобавленияПользователей |

Роли создайте сначала в пункте 2.13, затем вернитесь и назначьте их пользователям. Аутентификация 1С:Предприятия — включена. Пароль учебный: пустой, если платформа позволяет, иначе `12345`.

При первом входе элемент справочника **Пользователи** появится сам. Не создавайте эту строку руками.

Сохраните конфигурацию и обновите базу данных.

## 2.13. Роли

Ветка **Общие** → **Роли**.

### Роль ПолныеПрава

1. Правая кнопка мыши по **Роли** → **Добавить**.
2. **Имя:** `ПолныеПрава`. **Синоним:** `Полные права`.
3. В окне прав нажмите кнопку **Установить все права** (или отметьте все объекты вручную).
4. Право на интерактивное добавление справочника Пользователи — должно быть включено.

### Роль ПолныеПраваБезДобавленияПользователей

1. В дереве нажмите **правую кнопку мыши** по роли `ПолныеПрава`.
2. Выберите **Копировать**.
3. **Имя** копии: `ПолныеПраваБезДобавленияПользователей`. **Синоним:** `Полные права без добавления пользователей`.

Основная роль конфигурации: выделите корень `ГрумингСалон` → палитра → **Основные роли** → лупа → отметьте обе роли.

## 2.14. Подсистемы и командный интерфейс

### Состав (перетащите объекты в подсистему)

Откройте подсистему двойным щелчком → вкладка **Состав**. Отметьте объекты или перетащите их из дерева.

**Главное:** справочник Организации; начальная страница — журнал записей (см. ниже).

**Справочники:** Сотрудники, Должности, Номенклатура, ИсточникиПривлеченияКлиентов, ДоговорыКонтрагентов, Контрагенты, ПородыПитомцев, Склады.

**Покупки:** Контрагенты, ДоговорыКонтрагентов, Номенклатура, Склады, ПоступлениеТоваров.

**Продажи:** ЗаписьКлиента, РеализацияТоваровИУслуг, Контрагенты, ПородыПитомцев, ДоговорыКонтрагентов, Номенклатура, ИсточникиПривлеченияКлиентов, Склады, регистры Продажи, ЗаказыКлиентов, ТоварыНаСкладах.

**Персонал:** Сотрудники, Должности.

**Настройки:** Пользователи, константа ИспользоватьСклады.

### Командный интерфейс подсистемы

Правая кнопка мыши по подсистеме → **Открыть командный интерфейс**. Расставьте колонки **как в макетах**:

- Справочники: группы **Персонал** | **Продажи** | **Создать** (стандартные команды создания).
- Покупки: **Справочники** | **Покупки**.
- Продажи: **Продажи** | **Справочники** | **Создать**.
- Персонал: **Справочники** | **Создать**.
- Настройки: **Справочники** | **Сервис** (команда открытия константы / форма констант).

Для константы сделайте форму констант или команду, синоним `Использовать склады`. Как сделать форму констант: правая кнопка мыши по константе или ветка Общие формы → добавить форму констант, вывести флажок `ИспользоватьСклады`.

### Начальная страница

1. Выделите корень `ГрумингСалон`.
2. В палитре свойств найдите **Рабочая область начальной страницы** → лупа / **Открыть**.
3. Одна колонка. Добавьте форму списка `Документ.ЗаписьКлиента.Форма.ФормаСписка`.

Порядок подсистем в панели разделов: Главное, Справочники, Покупки, Продажи, Персонал, Настройки. Это настраивается так: правая кнопка мыши по корню конфигурации → **Открыть командный интерфейс конфигурации** → перетащите разделы в нужном порядке.

Сохраните конфигурацию и обновите базу данных.

## 2.15. Как самому проверить, что усвоены приёмы курса

Ревьюер смотрит не на «похожесть кнопок», а на приёмы:

1. Переключатель вместо выпадающего списка там, где в макете две кнопки.
2. Видимость элементов, а не удаление реквизитов.
3. Наименование договора и ФИО **собираются программно**, поле недоступно.
4. Сумма реализации в процедуре `ПередЗаписью`, не в каждом `ПриИзменении` таблицы.
5. Один цикл по товарам для двух регистров.
6. Движения заказов у реализации **только при основании**.
7. Печать без пустых таблиц.
8. Параметр сеанса плюс привилегированный общий модуль, а не ручной выбор автора.
9. Вторая роль без интерактивного создания пользователей.
10. Объекты разложены по подсистемам, начальная страница — журнал записей.

Если какой-то пункт «работает, но сделан иначе, чем в уроке» — переделайте по уроку.
