## 1.1. Перечисления — что это и куда их класть

Это **не** справочники, **не** документы и **не** строки, которые потом вбивают в карточку клиента.

**Перечисление** — короткий фиксированный список вариантов для выпадающего списка. На формах (файл 02, в этой же базе, сразу после этого файла) те же значения станут переключателем из двух кнопок. Сами значения вы создаёте один раз в Конфигураторе. В режиме 1С:Предприятие пользователь только **выбирает** «Клиент» или «Поставщик», новые пункты туда не добавляет.

**Куда класть:** левое дерево конфигурации → ветка **Перечисления** (рядом со справочниками, ниже корня `ГрумингСалон`). Если дерева нет: меню **Конфигурация** → **Открыть конфигурацию**.

Нужно **пять отдельных** перечислений. Каждое — свой объект. `Клиент` и `Поставщик` — это не два перечисления, а **два значения внутри одного** перечисления `ТипыКонтрагентов`.

### Как создать одно перечисление (повторите пять раз)

1. Слева найдите строку **Перечисления**.
2. Нажмите **правую кнопку мыши** по строке **Перечисления**.
3. В меню выберите **Добавить**.
4. Справа откроется палитра свойств. Заполните **Имя** (без пробелов) и **Синоним** (с пробелами, как в таблице ниже).
5. В окне перечисления откройте вкладку **Данные** (не «Формы», не «Макеты»).
6. Над списком значений нажмите **Добавить** (зелёный плюс). Для каждой строки заполните **Имя** и **Синоним**.
7. Сохраните конфигурацию и обновите базу данных (раздел 0.7 файла подготовки).

Пока **не** открывайте 1С:Предприятие и **не** ищите эти слова в карточках. К формам они привяжутся позже, когда у справочника появится реквизит с типом `ПеречислениеСсылка.…`.

| Перечисление (имя объекта) | Синоним объекта | Значения: имя → синоним | Зачем потом |
| --- | --- | --- | --- |
| `ТипыОрганизаций` | Типы организаций | `ЮридическоеЛицо` → Юридическое лицо; `ИндивидуальныйПредприниматель` → Индивидуальный предприниматель | реквизит Организации «Тип организации» |
| `ТипыКонтрагентов` | Типы контрагентов | `Клиент` → Клиент; `Поставщик` → Поставщик | реквизит Контрагенты «Тип контрагента» |
| `ВидыПитомцев` | Виды питомцев | `Кошка` → Кошка; `Собака` → Собака | порода и табличная часть «Питомцы» |
| `Полы` | Полы | `Мужской` → Мужской; `Женский` → Женский | сотрудник и клиент |
| `ТипыНоменклатуры` | Типы номенклатуры | `Услуга` → Услуга; `Товар` → Товар; `Материал` → Материал | номенклатура: услуга / товар / материал |

### ТипыОрганизаций

1. Правая кнопка мыши по **Перечисления** → **Добавить**.
2. Имя: `ТипыОрганизаций`. Синоним: `Типы организаций`.
3. Вкладка **Данные** → два значения:
   - Имя `ЮридическоеЛицо`, синоним `Юридическое лицо`
   - Имя `ИндивидуальныйПредприниматель`, синоним `Индивидуальный предприниматель`

### ТипыКонтрагентов

1. Снова правая кнопка мыши по **Перечисления** → **Добавить** (новый объект, не открывайте предыдущий).
2. Имя: `ТипыКонтрагентов`. Синоним: `Типы контрагентов`.
3. Вкладка **Данные** → два значения:
   - Имя `Клиент`, синоним `Клиент`
   - Имя `Поставщик`, синоним `Поставщик`

В дереве слева должно получиться: `Перечисления` → `ТипыКонтрагентов` → внутри значения `Клиент` и `Поставщик`.

### ВидыПитомцев

1. Правая кнопка мыши по **Перечисления** → **Добавить**.
2. Имя: `ВидыПитомцев`. Синоним: `Виды питомцев`.
3. Вкладка **Данные**:
   - Имя `Кошка`, синоним `Кошка`
   - Имя `Собака`, синоним `Собака`

Не путайте с справочником **Породы питомцев** (его создадите в пункте 1.6): там будут «Британская», «Болонка». Здесь только вид: кошка или собака.

### Полы

1. Правая кнопка мыши по **Перечисления** → **Добавить**.
2. Имя: `Полы`. Синоним: `Полы`.
3. Вкладка **Данные**:
   - Имя `Мужской`, синоним `Мужской`
   - Имя `Женский`, синоним `Женский`

Это общий список для сотрудников и клиентов. Отдельное перечисление «Пол клиента» создавать не нужно.

### ТипыНоменклатуры

1. Правая кнопка мыши по **Перечисления** → **Добавить**.
2. Имя: `ТипыНоменклатуры`. Синоним: `Типы номенклатуры`.
3. Вкладка **Данные** → **три** значения:
   - Имя `Услуга`, синоним `Услуга`
   - Имя `Товар`, синоним `Товар`
   - Имя `Материал`, синоним `Материал`

После этого в дереве под **Перечисления** ровно пять объектов. Если видите «Клиент» на одном уровне с «ТипыКонтрагентов» — вы создали лишнее перечисление вместо значения. Удалите его (правая кнопка мыши → **Удалить**) и добавьте `Клиент` как значение на вкладке **Данные** у `ТипыКонтрагентов`.

## 1.2. Справочник Должности

По учебному заданию у этого справочника только стандартные поля **Код** и **Наименование**. Свои реквизиты не добавляйте.

1. В дереве нажмите **правую кнопку мыши** по ветке **Справочники** → **Добавить**.
2. Откроется окно «Справочник». В палитре свойств (обычно справа или внизу):
   - **Имя:** `Должности`
   - **Синоним:** `Должности` (подставится сам, если не затрёте)
3. Вкладка **Нумерация** в этом же окне:
   - тип кода: **Строка**
   - длина кода: `9`
   - автонумерация: включена
4. Вкладка **Данные**:
   - **Длина наименования:** `150`
5. Закройте окно справочника крестиком, согласитесь сохранить. Затем сохраните конфигурацию и обновите базу данных.

Пока ничего не пишите в режиме 1С:Предприятие. Сначала создайте остальные справочники.

## 1.3. Справочник Сотрудники

### Что здесь вообще меняют

У каждого справочника платформа уже даёт два поля, их **не нужно создавать плюсиком**:

| Служебное имя (не меняется) | Зачем | Что должно быть написано на форме в макете |
| --- | --- | --- |
| `Код` | табельный номер | **Таб.№** |
| `Наименование` | полное ФИО одной строкой | **Ф.И.О.** |

Это и есть **стандартные реквизиты**. Вы меняете только подпись (свойство **Синоним**), а не имя объекта и не имя справочника.

Не делайте так:

- не создавайте новый реквизит с именем `ТабНомер` или `ФИО`;
- не пишите `Таб.№` в имя самого справочника (справочник по-прежнему `Сотрудники`);
- не ищите эти слова в режиме 1С:Предприятие, пока не обновили базу данных — их нет в карточках «просто так», это подписи полей.

### Шаг A. Создать справочник

1. Правая кнопка мыши по **Справочники** → **Добавить**.
2. **Имя:** `Сотрудники`. **Синоним:** `Сотрудники`.
3. Вкладка **Нумерация:** тип кода Строка, длина `9`, автонумерация включена.
4. Вкладка **Данные:** **Длина наименования** = `150`.
   Это поле именно на вкладке **Данные** окна справочника, не в «стандартных реквизитах».

### Шаг B. Открыть список стандартных реквизитов (сюда вводить Таб.№ и Ф.И.О.)

**Не трогайте** верхнее поле **Синоним: Сотрудники** — это имя всего справочника, не табельный номер.

Смотрите **правую** панель «Свойства: Сотрудники». Прокрутите её вниз, в группе **Данные**, сразу под строкой **Автонумерация**.

Там есть строка:

**Стандартные реквизиты** ………… кнопка **Открыть**

1. Нажмите именно **Открыть** (в других сборках вместо слова «Открыть» бывает лупа).
2. Появится отдельное окно со списком: `Код`, `Наименование`, `ПометкаУдаления` и другие.
3. Дважды щёлкните строку **Код**.
4. Палитра справа сменит заголовок на свойства **Кода**. Найдите **Синоним** (сейчас там `Код`).
5. Замените на `Таб.№` и щёлкните любое другое поле, чтобы значение зафиксировалось.
6. Вернитесь в список, дважды щёлкните **Наименование**, синоним = `Ф.И.О.`

Пока не нажали **Открыть**, поля «Синоним Кода» в окне справочника **нет** — его специально спрятали внутрь этого списка.

На том же правом списке свойств справочника сразу поправьте:

- **Иерархический** — снимите флажок. У сотрудников не должно быть групп и «родителя».
- **Длина наименования** — поставьте `150`, не `25` (иначе длинное ФИО не влезет).

### Шаг C. Синоним Кода = Таб.№

После **Открыть** у стандартных реквизитов:

1. Дважды щёлкните **Код**.
2. В палитре свойств реквизита Код найдите **Синоним**.
3. Впишите `Таб.№` (буква Т, точка, знак номера).

Имя реквизита так и останется `Код`. Меняется только подпись на карточке.

### Шаг D. Синоним Наименования = Ф.И.О.

1. В том же списке после **Открыть** дважды щёлкните **Наименование**.
2. **Синоним** = `Ф.И.О.`
3. Закройте окна. Сохраните конфигурацию и обновите базу данных.

На макете карточки сотрудника сверху будет:

- слева подпись **Таб.№:** — это стандартный Код;
- слева подпись **Ф.И.О.:** — это стандартное Наименование (пока обычное поле; на спринте 2 его заблокируют и будут собирать из Фамилия + Имя + Отчество).

### Шаг E. Свои реквизиты (уже плюсиком, вкладка Данные)

Это **другие** поля. Их нет среди стандартных. Откройте справочник `Сотрудники` → вкладка **Данные** → над таблицей реквизитов зелёный **+**.

Для каждого: имя, синоним, тип. Обязательность: свойство **Проверка заполнения** = **Выдавать ошибку**.

| Имя (без пробелов) | Синоним (подпись на форме) | Тип | Как выбрать тип | Обязательный |
| --- | --- | --- | --- | --- |
| Фамилия | Фамилия | Строка, длина 50 | Тип → Строка → длина 50 | Да |
| Имя | Имя | Строка, длина 50 | так же | Да |
| Отчество | Отчество | Строка, длина 50 | так же | Нет |
| Пол | Пол | перечисление Полы | Тип → ссылка на перечисление → `Полы` | Да |
| ДатаРождения | Дата рождения | Дата | Дата, состав «Дата» | Нет |
| Должность | Должность | справочник Должности | Тип → ссылка на справочник → `Должности` | Нет |
| КонтактныйТелефон | Контактный телефон | Строка, длина 20 | Строка, длина 20 | Нет |

Тип «ссылка на перечисление»: в окне типа слева **ПеречислениеСсылка**, справа выберите `Полы`.

Тип «ссылка на справочник»: слева **СправочникСсылка**, справа `Должности`.

Форму элемента здесь не рисуйте: платформа покажет поля сама. В файле 02 поле Ф.И.О. станет только для просмотра и будет собираться из фамилии, имени и отчества.

Сохраните конфигурацию и обновите базу данных.

## 1.4. Справочник Организации

1. Правая кнопка мыши по **Справочники** → **Добавить**.
2. **Имя:** `Организации`. **Синоним:** `Организации`.
3. Вкладка **Нумерация:** тип кода Строка, длина `9`, автонумерация включена.
4. Вкладка **Данные:** длина наименования `150`.
5. На той же вкладке **Данные**, в таблице реквизитов (ещё пустая) нажмите зелёный **+**. Добавьте поля по таблице ниже.
6. После каждого реквизита: выделите его в списке → палитра свойств → **Проверка заполнения** = **Выдавать ошибку**, если в колонке «Обязательный» стоит Да.

Как выбрать тип (окно «Тип данных», кнопка с буквой **T** у свойства Тип):

- **Строка:** слева «Строка», длина 12, переменная.
- **Перечисление:** слева `ПеречислениеСсылка`, справа `ТипыОрганизаций`.
- **Справочник:** слева `СправочникСсылка`, справа `Сотрудники` или `Должности`.

| Имя | Синоним | Тип | Обязательный |
| --- | --- | --- | --- |
| ТипОрганизации | Тип организации | ПеречислениеСсылка.ТипыОрганизаций | Да |
| ИНН | ИНН | Строка, длина 12 | Да |
| Руководитель | Руководитель | СправочникСсылка.Сотрудники | Нет |
| ДолжностьРуководителя | Должность руководителя | СправочникСсылка.Должности | Нет |
| ГлавныйБухгалтер | Главный бухгалтер | СправочникСсылка.Сотрудники | Нет |

Почему Руководитель — ссылка на сотрудника, а не строка: одно ФИО хранится в справочнике «Сотрудники», организация на него ссылается. Так учат на уроках.

Форму элемента здесь не создавайте: её нарисуете в файле 02 в этой же базе, сразу после этого файла. Сохраните конфигурацию и обновите базу данных.

## 1.6. Справочник ПородыПитомцев

Здесь три отдельные настройки: иерархия, подпись «Порода», предопределённые **группы** Кошки и Собаки.

### Шаг A. Создать справочник и включить дерево

1. Правая кнопка мыши по **Справочники** → **Добавить**.
2. **Имя:** `ПородыПитомцев`. **Синоним:** `Породы питомцев`.
3. Откройте вкладку **Иерархия** (в окне справочника, рядом с «Данные»).
4. Поставьте флажок **Иерархический справочник**.
5. **Вид иерархии:** `Иерархия групп и элементов` (не «иерархия элементов»).
6. **Размещать группы сверху:** да (если есть такой флажок).
7. Вкладка **Нумерация:** строка, длина 9, автонумерация включена.
8. Вкладка **Данные:** длина наименования `100`.

### Шаг B. Подпись Наименования = Порода

1. Выделите справочник в дереве одним щелчком.

## Как нажать «Связи параметров выбора» (ОсновнойДоговор и ПородаПитомца)

Это **не** строка **Параметры выбора**. Рядом в палитре есть две похожие строки:

| Строка в свойствах | Когда нужна |
| --- | --- |
| **Параметры выбора** | постоянный отбор, например «всегда только Клиент» |
| **Связи параметров выбора** | отбор **от другого поля этой же карточки** — вот оно |

Для договоров и пород нужна именно **Связи параметров выбора**.

Окно такое же по духу, как **Стандартные реквизиты → Открыть**: строка в правой палитре и кнопка **Открыть**.

### Задача 1. Основной договор — только договоры этого контрагента

Смысл: у Летяевой в списке не должно быть договора ООО «Бонифаций». Владелец договора = текущий контрагент (`Ссылка`).

1. Справочник **Контрагенты** открыт, вкладка **Данные**.
2. В **верхнем** списке реквизитов один раз щёлкните `ОсновнойДоговор` (строка должна подсветиться).
3. Справа палитра сменит заголовок на свойства **этого реквизита** (не всего справочника). Если всё ещё «Свойства: Контрагенты» — щёлкните реквизит ещё раз.
4. Прокрутите правую палитру. Найдите **Связи параметров выбора** (не «Параметры выбора»).
5. Справа нажмите **Открыть**.
6. Пустое окно. Нажмите **Добавить** (зелёный плюс). Справа в таблице **Параметры** появится строка.
7. Колонка **Имя:** наберите `Отбор.Владелец` (точка, без пробелов).
8. Слева в **Доступные реквизиты** щёлкните `Ссылка`.
9. Кнопка **>** — колонка **Реквизит** справа заполнится значением `Ссылка`.
10. Нажмите **ОК**. Сохраните конфигурацию (клавиши Ctrl и S).

`Ссылка` — это «этот контрагент», стандартное поле, плюсиком его создавать не нужно.

Если в списке нет `Ссылка`: раскройте ветку объекта и ищите стандартный реквизит **Ссылка**.

### Задача 2. Порода питомца — только породы выбранного вида

Смысл: в строке «Кошка» нельзя выбрать «Болонка».

1. Тот же справочник **Контрагенты**, вкладка **Данные**.
2. Внизу щёлкните табличную часть `Питомцы`, чтобы она стала текущей.
3. В списке реквизитов **табличной части** (колонки таблицы «Питомцы») один раз щёлкните `ПородаПитомца`.
4. Справа — свойства реквизита табличной части. Строка **Связи параметров выбора** → **Открыть**.
5. **Добавить**. Справа появится строка в таблице **Параметры**.
6. Колонка **Имя** (правая таблица): `Отбор.ВидПитомца`.
7. Слева в **Доступные реквизиты** найдите и щёлкните `Питомцы.ВидПитомца` (не путайте с полями шапки карточки).
8. Нажмите кнопку **>** между списками. В колонке **Реквизит** справа должно появиться `Питомцы.ВидПитомца`.
9. **Режим изменения** оставьте `Очищать` — если сменили вид с кошки на собаку, порода сбросится.
10. **ОК**, затем сохраните конфигурацию и обновите базу данных.

У справочника **ПородыПитомцев** реквизит должен называться именно `ВидПитомца`. Иначе отбор не к чему привязать.

### Частые ошибки

- Открыли **Параметры выбора** вместо **Связи параметров выбора** — связи там нет, закройте и возьмите соседнюю строку.
- Палитра показывает свойства всего справочника — вы не выделили реквизит в таблице.
- Имя с пробелом: `Отбор. Владелец` не сработает. Только `Отбор.Владелец`.
- Для поступления товаров позже так же: реквизит документа `Договор`, связь `Отбор.Владелец` = реквизит шапки `Поставщик`.

## 1.12. Документ ЗаписьКлиента

Документ — это не справочник. В дереве это другая ветка: **Документы**.

4. Стандартные реквизиты документа **Номер** и **Дата** уже есть, плюсиком их не добавляйте. Дата обязательна: стандартные реквизиты → **Открыть** → **Дата** → проверка заполнения = Выдавать ошибку.

### Шаг B. Реквизиты шапки

Вкладка **Данные**, верхняя таблица, **+**.

Тип «дата и время»: в окне типа **Дата**, состав **Дата и время**.

Тип «неограниченная строка»: Строка, длина `0`.

| Имя | Синоним | Тип | Обязательный |
| --- | --- | --- | --- |
| Клиент | Клиент | СправочникСсылка.Контрагенты | Да |
| Сотрудник | Сотрудник | СправочникСсылка.Сотрудники | Да |

| Ответственный | Ответственный | СправочникСсылка.Пользователи | Нет |

### Шаг C. Чтобы в Клиенте не выбирались поставщики

Нужна строка **Параметры выбора** (у вас она уже есть — это правильно).

**Связи параметров выбора** для этого поля оставьте пустыми.

**Выбор групп и элементов = Элементы** — тоже правильно: папку «Клиенты» выбрать как клиента нельзя.

Само значение справа не должно быть `Клиент(Клиенты)`. Так получается, если отбор по **группе** «Клиенты». Нужен отбор по **типу контрагента**.

После настройки в палитре должно быть примерно:

`Отбор.ТипКонтрагента(Клиент)`

Как выставить:

1. Реквизит `Клиент` выделен.
2. Строка **Параметры выбора** → кнопка с точками (не крестик).
3. Если в списке уже есть строка вроде `Клиент` / `Клиенты` — удалите её.
4. **Добавить**.
5. **Имя:** `Отбор.ТипКонтрагента` (с точкой, как у связей, но это другое окно).
6. **Значение:** выбор → перечисление **ТипыКонтрагентов** → **Клиент** (не папка справочника «Клиенты»).
7. ОК.

То же самое у документа реализации для реквизита `Клиент`.

У поступления для `Поставщик`: имя `Отбор.ТипКонтрагента`, значение **Поставщик**.

### Шаг D. Табличная часть «Услуги» у документа «Запись клиента»

Табличная часть — это таблица внизу документа (строки услуг). Её добавляют не плюсом в верхнем списке реквизитов, а в нижнем блоке вкладки **Данные**.

1. Откройте документ `ЗаписьКлиента`, вкладка **Данные**.
2. Внизу найдите заголовок **Табличные части**.

### Реализация → расход склада и обороты продаж

Окно конструктора должно быть таким: документ реализация, регистр **ТоварыНаСкладах**, тип **Расход**, табличная часть **Товары**. Галочки ТоварыНаСкладах и Продажи у реализации — да.

У поступления галочка только **ТоварыНаСкладах**. **Продажи** у поступления не включайте.

#### Первый заход — склад

В нижней таблице три строки. Колонка **Выражение** заполняется не словом «шапка», а именем поля.

Как заполнить выражение: щёлкните ячейку **Выражение**, затем **дважды щёлкните поле справа** в списке «Реквизиты документа» или в списке колонок табличной части (когда выбрана табличная часть Товары).

| Поле регистра | Что должно стоять в «Выражение» | Откуда взять двойным щелчком |
| --- | --- | --- |
| Номенклатура | `Товар` | колонка табличной части Товары |
| Склад | `Склад` | справа в реквизитах документа строка **Склад** |
| Количество | `Количество` | колонка табличной части Товары |

Если Количество = **Сумма** — это ошибка. Щёлкните выражение Сумма, сотрите, дважды щёлкните **Количество**.

Если Склад = **шапка** — тоже ошибка. Слово «шапка» вписывать не надо. Щёлкните это выражение и дважды щёлкните **Склад** в правом списке реквизитов документа.

Кнопка **ОК** (или **Выполнить** / готово в вашей версии). Согласитесь создать процедуру проведения.

#### Второй заход — продажи по товарам

Снова вкладка **Движения** → **Конструктор движений**.

1. Слева выберите регистр **Продажи**.
2. Табличная часть: **Товары**.
3. Соответствие:

| Поле регистра | Выражение |
| --- | --- |
| Номенклатура | `Товар` |
| Сотрудник | `Сотрудник` (справа, реквизит шапки документа) |
| Клиент | `Клиент` (справа, реквизит шапки документа) |
| Сумма | `Сумма` (колонка табличной части Товары, не СуммаДокумента) |

ОК. Если спросит «добавить к существующей процедуре» — да.

#### Третий заход — продажи по услугам

Ещё раз конструктор, регистр снова **Продажи**, табличная часть уже **Услуги**:

| Поле регистра | Выражение |
| --- | --- |
| Номенклатура | `Услуга` |
| Сотрудник | `Сотрудник` |
| Клиент | `Клиент` |
| Сумма | `Сумма` |

ОК. Сохраните конфигурацию и обновите базу данных.

На спринте 1 в модуле реализации будет два цикла по товарам — так и должно быть. Не склеивайте циклы руками.

Для **поступления** конструктор один раз: регистр ТоварыНаСкладах, тип **Приход** (не Расход), табличная часть Товары, выражения Товар / Склад / Количество. Не Сумма.

### Если проверка пишет «Переменная не определена (Товар)» или «(Количество)»

Конструктор записал поле **шапки**, а не колонку строки. В модуле сейчас так:

```
Движение.Номенклатура = Товар;
Движение.Количество = Количество;
```

Так нельзя: у документа нет реквизитов шапки `Товар` и `Количество`. Они живут в строке табличной части. Должно быть:

```
Движение.Номенклатура = ТекСтрокаТовары.Товар;
Движение.Количество = ТекСтрокаТовары.Количество;
```

Для цикла по услугам:

```
Движение.Номенклатура = ТекСтрокаУслуги.Услуга;
Движение.Сумма = ТекСтрокаУслуги.Сумма;
```

Склад, сотрудник, клиент, дата — из шапки, без `ТекСтрока…`: `Склад`, `Сотрудник`, `Клиент`, `Дата`.

Имена `ТекСтрокаТовары` и `ТекСтрокаУслуги` должны **в точности** совпасть со строкой `Для Каждого … Из`. Не переключайте раскладку посередине слова: латинская буква вместо русской даст ту же ошибку.

Комментарии конструктора `//{{__КОНСТРУКТОР_ДВИЖЕНИЙ_РЕГИСТРОВ` не удаляйте. После правки строк не запускайте конструктор заново — он затрёт исправления.

## 1.18. Печатная форма реализации

Учебный курс обычно печатает **командой формы**, без библиотеки стандартных подсистем. Делайте как на уроке печати. Ниже — тот же приём по шагам.

### Шаг A. Макет табличного документа

1. В дереве раскройте документ `РеализацияТоваровИУслуг` → правая кнопка мыши по **Макеты** → **Добавить**.
2. Тип макета: **Табличный документ**.
3. **Имя:** `ПФ_MXL_РеализацияТоваровИУслуг`.
4. **Синоним:** `Реализация товаров и услуг`.
5. Откроется сетка как в Excel.

Именованные области (обязательно, иначе код не найдёт куски):

1. Выделите несколько первых строк (например 1–8) мышью за номера строк слева.
2. Правая кнопка мыши по выделенным номерам строк → **Свойства**.
3. **Имя:** `Заголовок`. Закройте свойства.
4. В ячейках этой области напишите заголовок `Реализация товаров и услуг` и подписи Номер, Дата, Клиент, Сотрудник, Основание.
5. В ячейках справа от подписей в свойствах ячейки (двойной щелчок или правая кнопка мыши → Свойства) поле **Заполнение** = **Параметр**, имена параметров: `Номер`, `Дата`, `Клиент`, `Сотрудник`, `Основание`.

Дальше так же именуйте области:

| Имя области | Что внутри |
| --- | --- |
| ШапкаУслуг | шапка таблицы: №, Услуга, Сумма |
| СтрокаУслуг | параметры `НомерСтроки`, `Услуга`, `Сумма` |
| ШапкаТоваров | №, Товар, Количество, Цена, Сумма |
| СтрокаТоваров | параметры `НомерСтроки`, `Товар`, `Количество`, `Цена`, `Сумма` |
| Подвал | подписи Сумма документа, Ответственный и параметры `СуммаДокумента`, `Ответственный` |

Параметр ячейки: свойства ячейки → Заполнение = Параметр → имя как в таблице.

### Шаг B. Команда Печать на форме документа

Пока основной формы нет, платформа откроет автоформу. Команду всё равно повесьте на документ:

1. Правая кнопка мыши по документу в дереве → ветка **Команды** → **Добавить**.
2. **Имя:** `Печать`. **Синоним:** `Печать`.
3. **Группа:** командная панель формы.
4. **Тип параметра команды:** можно оставить ссылку на документ.
5. Откройте **модуль команды** (кнопка в окне команды).

Если на уроке команду ставили **на форму**, повесьте её в файле 02, когда появится форма документа. Сейчас достаточно макета и вызова из модуля менеджера / команды.

Простой вариант «как в уроке» — общий модуль не обязателен. В **модуле менеджера** документа (правая кнопка мыши по документу → **Открыть модуль менеджера**) вставьте функцию и оставьте вызов из команды:

```
Функция СформироватьПечатнуюФорму(Документ) Экспорт

	ТабДок = Новый ТабличныйДокумент;
	Макет = Документы.РеализацияТоваровИУслуг.ПолучитьМакет("ПФ_MXL_РеализацияТоваровИУслуг");

	ОбластьЗаголовок = Макет.ПолучитьОбласть("Заголовок");
	ОбластьЗаголовок.Параметры.Заполнить(Документ);
	ТабДок.Вывести(ОбластьЗаголовок);

	Если Документ.Услуги.Количество() > 0 Тогда
		ТабДок.Вывести(Макет.ПолучитьОбласть("ШапкаУслуг"));
		ОбластьСтрока = Макет.ПолучитьОбласть("СтрокаУслуг");
		НомерСтроки = 0;
		Для Каждого СтрокаТЧ Из Документ.Услуги Цикл
			НомерСтроки = НомерСтроки + 1;
			ОбластьСтрока.Параметры.Заполнить(СтрокаТЧ);
			ОбластьСтрока.Параметры.НомерСтроки = НомерСтроки;
			ТабДок.Вывести(ОбластьСтрока);
		КонецЦикла;
	КонецЕсли;

	Если Документ.Товары.Количество() > 0 Тогда
		ТабДок.Вывести(Макет.ПолучитьОбласть("ШапкаТоваров"));
		ОбластьСтрока = Макет.ПолучитьОбласть("СтрокаТоваров");
		НомерСтроки = 0;
		Для Каждого СтрокаТЧ Из Документ.Товары Цикл
			НомерСтроки = НомерСтроки + 1;
			ОбластьСтрока.Параметры.Заполнить(СтрокаТЧ);
			ОбластьСтрока.Параметры.НомерСтроки = НомерСтроки;
			ТабДок.Вывести(ОбластьСтрока);
		КонецЦикла;
	КонецЕсли;

	ОбластьПодвал = Макет.ПолучитьОбласть("Подвал");
	ОбластьПодвал.Параметры.СуммаДокумента = Документ.СуммаДокумента;
	ОбластьПодвал.Параметры.Ответственный = Документ.Ответственный;
	ТабДок.Вывести(ОбластьПодвал);

	Возврат ТабДок;

КонецФункции
```

Модуль команды (клиент):

```
&НаКлиенте
Процедура ОбработкаКоманды(ПараметрКоманды, ПараметрыВыполненияКоманды)
	ТабДок = ПечатьНаСервере(ПараметрКоманды);
	ТабДок.Показать("Реализация товаров и услуг");
КонецПроцедуры

&НаСервере
Функция ПечатьНаСервере(Документ)
	Возврат Документы.РеализацияТоваровИУслуг.СформироватьПечатнуюФорму(Документ);
КонецФункции
```

Если платформа ругается, что в модуле команды нельзя `&НаСервере`, вынесите серверный вызов в общий модуль с флажком «Вызов сервера», как показывали на уроке. **Не** копируйте `УправлениеПечатью` из библиотеки стандартных подсистем — в учебной базе этой подсистемы обычно нет.

Пропуск пустых табличных частей (`Если Количество() > 0`) заложите сразу: это же понадобится при проверке печати после файла 02.

Сохраните конфигурацию и обновите базу данных.

## 1.19. Функциональная опция складов

Нужны **два разных объекта**. Они лежат в **разных** ветках дерева. Не ищите оба в «Справочниках».

| Объект | Где в дереве 8.3.27 |
| --- | --- |
| Константа `ИспользоватьСклады` | верхний уровень, ветка **Константы** (рядом со Справочниками, не внутри Общие) |
| Функциональная опция `ИспользоватьСклады` | ветка **Общие** → **Функциональные опции** |

Имена могут совпасть — это нормально: константа хранит флажок, опция прячет объекты, когда флажок снят.

---

### Шаг A. Константа

1. В дереве слева найдите ветку **Константы**. Если дерева нет: меню **Конфигурация** → **Открыть конфигурацию**. Если ветки не видно — раскройте корень `ГрумингСалон` плюсиком. **Константы** идут после блока **Общие**, перед **Справочники**.
2. Нажмите **правую кнопку мыши** по строке **Константы**.
3. Выберите **Добавить**.
4. Палитра свойств (справа). Заголовок должен быть про константу, не про корень конфигурации.
5. **Имя:** `ИспользоватьСклады` — без пробелов, слитно.
6. **Синоним:** `Использовать склады`.
7. **Тип:** кнопка с буквой **T** → слева галочка только **Булево** → **ОК**. В палитре тип станет `Булево`.
8. Другие поля не трогайте. Закройте окно константы крестиком, согласитесь сохранить.

В дереве должно появиться: **Константы** → `ИспользоватьСклады`.

---

### Шаг B. Функциональная опция

1. В дереве раскройте ветку **Общие** (самая верхняя папка под корнем, жёлтая).
2. Внутри найдите **Функциональные опции**. Это не «Параметры функциональных опций» (соседняя строка — её не открывайте).
3. **Правая кнопка мыши** по **Функциональные опции** → **Добавить**.
4. Палитра свойств опции:
   - **Имя:** `ИспользоватьСклады`
   - **Синоним:** `Использовать склады`
5. Строка **Хранение**. Справа нажмите лупу / **Открыть** / кнопку выбора.
6. В списке выберите константу `ИспользоватьСклады` (та, что создали в шаге A). Не создавайте вторую константу.
7. **ОК**. В палитре у «Хранение» должно стоять `Константа.ИспользоватьСклады`.

Если **Хранение** оставить пустым, опция не заработает.

---

### Шаг C. Состав опции (что прятать)

1. Окно функциональной опции открыто. Найдите вкладку **Состав** (рядом с «Основные» / в центре окна).  
   Если вкладки нет: в палитре свойство **Состав** → кнопка **Открыть**.
2. Откроется дерево объектов конфигурации с флажками. Отметьте **ровно это**:

| Где раскрыть | Что отметить |
| --- | --- |
| **Справочники** | строка `Склады` |
| **Документы** → `РеализацияТоваровИУслуг` → **Реквизиты** | реквизит `Склад` |
| **Документы** → `ПоступлениеТоваров` → **Реквизиты** | реквизит `Склад` |
| **Регистры накопления** | строка `ТоварыНаСкладах` |
| **Регистры накопления** → `ТоварыНаСкладах` → **Измерения** | измерение `Склад` |

Как отмечать: раскройте плюсики до нужной строки и поставьте галочку **на самой строке** (`Склад`, не на всём документе).

Не отмечайте весь документ «Реализация» и весь документ «Поступление». Иначе при снятом флажке пропадут сами документы, а не только поле склада.

3. Закройте окно состава / опции, согласитесь сохранить.

---

### Шаг D. Сохранить и обновить

1. Меню **Конфигурация** → **Сохранить конфигурацию** (клавиши Ctrl и S).
2. Меню **Конфигурация** → **Обновить конфигурацию базы данных** (клавиша F7).
3. **Принять**.

---

### Шаг E. Включить флажок в 1С:Предприятие

После обновления константа обычно **выключена**. Тогда склады скрыты. Для проверки и для демо-данных включите её.

1. **Отладка** → **Начать отладку** (или из списка баз кнопка **1С:Предприятие**).
2. Кружок 1С слева сверху. Если нет **Все функции**: **Сервис** → **Параметры** → флажок **Отображать команду «Все функции»** → **ОК**, снова откройте меню.
3. **Все функции** → **Константы** → `Использовать склады`.
4. Поставьте флажок (Да / Истина) → запишите.
5. Закройте предприятие и откройте снова, чтобы интерфейс обновился.

Проверка: поле **Склад** в поступлении и реализации видно, справочник **Склады** открывается. Если снять флажок и перезайти — поле и справочник пропадут. Перед сдачей флажок держите **включённым**, иначе складские движения некуда писать.

Подсистему «Настройки» и форму константы рисовать сейчас не нужно — это файл 02.

## 1.20. Что проверить в режиме 1С:Предприятие

Данные для полей — в [03-dannye.md](03-dannye.md). Подсистем ещё нет: **Все функции** → **Справочники** / **Документы**.

1. Породы: **Ещё** → Режим просмотра → **Дерево**, папки Кошки и Собаки на месте, внутри хотя бы по три породы.
2. Контрагенты: дерево, папки Клиенты и Поставщики, внутри клиенты и поставщики.
3. Договор с владельцем ООО «Бонифаций». В поступлении список договоров не показывает чужие.
4. Запись клиента проведена (кнопка **Провести**; движений заказов ещё нет — регистр появится в файле 02). Это нормально: регистр заказов ещё впереди.
5. Из записи: **Создать на основании** → Реализация: клиент, сотрудник, услуги, комментарий подставились.
6. Поступление проведено. **Все функции** → Регистр накопления **Товары на складах** → есть приход.
7. Реализация проведена: по складу расход, в регистре **Продажи** строки услуг и товаров.
8. Кнопка **Печать** открывает табличный документ.
9. Константа складов: снимите флажок, перезайдите — склады пропадают из интерфейса. Верните флажок.

Код `ОбработкаПроведения` оставьте конструкторским, на русском. Комментарии `//{{__КОНСТРУКТОР_ДВИЖЕНИЙ_РЕГИСТРОВ` не удаляйте до пункта 2.9.
